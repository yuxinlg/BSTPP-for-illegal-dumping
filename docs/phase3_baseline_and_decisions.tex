\subsubsection{10.d Polygon excitation support modes}\label{d-polygon-excitation-support-modes}}

\textbf{Scientific contract (D-2/D-3, D-13/D-14):} A is the scientific and observed domain; observed events outside A rejected; final reported/simulated events lie in A; infinite-support kernels are the scientific target.

\textbf{Two supported computational modes on nonrectangular domains (D-17):}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Bounding-rectangle excitation approximation.} May allow offspring in R ~A to participate in the cascade before final observation-domain filtering, \emph{if declared}; must charge the matching rectangle-support mass; labeled explicitly approximate for nonrectangular A; mode recorded in fit and simulation provenance. (This is the tip's verified behavior, §5.11--5.12, made explicit and opt-in.)
\item
  \textbf{Polygon-domain excitation mass/support.} Offspring leaving A are discarded before parenting; compensator charges mass over A, subject to the declared cutoff approximation and numerical accuracy; numerical method, tolerance, interpolation behavior, and error control documented and tested.
\end{enumerate}

\textbf{Per-mode consistency invariant (D-18):} within a mode, the offspring parenting-eligibility region ≡ the compensator charge region. Mixing a rectangle simulator leg with a polygon compensator leg (or vice versa) must be \textbf{structurally impossible} --- one support object feeds both legs, following the tip's single-sourced-predicate pattern for w\_s (§5.9), which is the template.

\textbf{Rectangle degeneracy (mandatory acceptance test):} when A is an axis-aligned rectangle, the two modes coincide (within declared tolerance; bit-identical where operation ordering permits).

\textbf{Default selection --- proposed, not settled (OP-2):} nonrectangular Hawkes/Cox--Hawkes domain with no support mode specified → \textbf{loud error requiring an explicit choice}. Not silently adopted without reviewer acceptance.

\textbf{Polygon-mass diagnostic (specification in §13):} informs the accuracy target, precomputation/interpolation vs.~direct quadrature, runtime expectations, and guidance on when rectangle mode is adequate. It does \textbf{not} determine whether polygon mode exists. District geometry availability is an external dependency (§6.18).

\hypertarget{polygon-diagnostic-specification}{%
\subsection{13. Polygon diagnostic specification}\label{polygon-diagnostic-specification}}

\textbf{Purpose:} quantify the rectangle-vs-polygon excitation-mass discrepancy on the Philadelphia district geometries to set the polygon-mode accuracy target and advise when rectangle mode is adequate. It does not decide whether polygon mode exists (D-17).

\textbf{Inputs:} district polygons (external dependency, §6.18); event locations per district; σ grid spanning representative values ≈ 10--500 m (log-spaced, e.g., 10, 20, 50, 100, 200, 500 m).

\textbf{Computation, per district and per σ:} for each event location s\_j (or a boundary-stratified subsample), the rectangle spatial mass M\_rect(s\_j; σ) --- the per-axis erf product of §5.12, optionally window-clipped --- and a high-accuracy polygon reference M\_poly(s\_j; σ) (adaptive quadrature or dense-grid summation with convergence check). Report as a \textbf{function of σ}, not at a single posterior estimate --- α and most of the temporal factor scale out of the relative comparison.

\textbf{Per-district outputs:}

\begin{itemize}
\tightlist
\item
  median and maximum spatial-mass difference M\_rect − M\_poly;
\item
  relative excitation-compensator overcharge Σ(M\_rect − M\_poly)/ΣM\_poly;
\item
  fraction of events within 1σ, 2σ, 3σ of ∂A;
\item
  variation across districts (identifies districts that fill their bounding boxes poorly);
\item
  cost of the high-accuracy polygon reference (wall time, memory);
\item
  the accuracy required of a production polygon-mass method (tolerance such that the induced compensator error is dominated by the declared cutoff ε and float tolerance).
\end{itemize}

\textbf{Consumers:} OP-9 (numerical method + accuracy target); NUTS runtime expectations (baseline cost profile in §10.g); user guidance for mode selection; 3d test tolerances.
